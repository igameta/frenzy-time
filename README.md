# FRENZY TIME

文化祭のタイムテーブルと、2フロアまでのTwitch映像・コメントを表示する静的サイトです。開発サーバーにViteを使用します。Wranglerを含む開発環境にはNode.js 22.12以降が必要です。

```sh
npm ci
npm run dev
```

`http://127.0.0.1:5173` を開きます。使用中の場合は、ターミナルに表示されるURLを使用してください。タイムテーブルは `/index.html`、配信ページは `/live.html` です。`file://` ではCSV読み込みやTwitchが動作しません。

開発中は、CSSの変更がHMRで即時反映され、JavaScript・HTMLの変更時にはページが自動で再読み込みされます。Vite開発サーバーでは公開スプレッドシートを `data.refreshMs` の間隔で取得し、タブ復帰時にも取得します。本番ビルドでは初回表示時のみ取得し、定期取得とタブ復帰時の自動取得は行いません。Viteの導入方法・動作は[公式ガイド](https://vite.dev/guide/)を参照してください。

## 設定

### OGP

タイムテーブルと配信ページに、共通の `assets/ogp.png`（1200×630px）を設定しています。採用デザインは「タイポ・インパクト」で、TDUの青・大きなイベント名・FRENZY.NETのロゴ・開催日を掲載しています。画像内の日程は固定のため、開催日を変更するときは画像も更新してください。

OGPとXの大きな画像カード用のメタデータは、JavaScriptを実行しないクローラーでも取得できるように各HTMLへ直接記述しています。画像URL・ページURLは `https://frenzy-time.igameta.com` を使用し、配信ページは実際の転送先 `/live` に揃えています。公開ドメインを変更する場合は、両HTMLのOGP・X用メタデータとcanonical URLを更新してください。

### 基本設定

`config.js` のイベント名、フロア名、各フロアの `twitchChannel` を設定してください。チャンネル名はURL全体ではなく `example_channel` の部分です。空欄の場合は配信準備中と表示します。

`useSampleData: true` にすると、架空の2027年11月6日・7日のサンプルを表示します。Vite開発サーバーではサンプル・公開スプレッドシートのどちらでも、画面上の「公演前／開演後／終演後」でタイムテーブルを切り替えて確認できます。`?preview=during` などのパラメーターを使用し、指定がなければ現在時刻で表示します。配信ページとの移動時も選択状態を引き継ぎます。本番ビルドおよび `npm run dev:worker` では切り替えを表示せず、`preview` パラメーターも無効です。

開演後プレビューでは実際に読み込んだ予定内の時刻を使います。`demo.duringAt` はサンプルデータでのみ参照し、出演枠の期間外なら予定内の時刻に置き換えます。プレビューは表示上の時刻だけを変更し、公開CSVには書き込みません。

### 公開スプレッドシート

Googleスプレッドシートに `schedule` と `djs` の2つのタブを作成します。「ファイル → 共有 → ウェブに公開」で各タブを**CSV形式**で公開し、それぞれのURLを取得してください。ブラウザで開く編集用・閲覧用URLではなく、CSVを返すURLを使用します。

```js
data: {
  useSampleData: false,
  scheduleUrl: 'https://docs.google.com/spreadsheets/d/e/PUBLISHED_ID/pub?gid=SCHEDULE_GID&single=true&output=csv',
  djsUrl: 'https://docs.google.com/spreadsheets/d/e/PUBLISHED_ID/pub?gid=DJS_GID&single=true&output=csv',
  refreshMs: 60_000,
},
```

実データの検証中は、公開URLに第三者がアクセスでき、CORS制限がなくCSVが返ることを確認してください。公開シートには個人情報や認証情報を置かないでください。

#### schedule

| 列 | 必須 | 内容 |
| --- | --- | --- |
| `floor_id` | ○ | `config.js` のフロアIDと一致（例：`floor-1`） |
| `start_at` | ○ | `2027-11-07T13:00:00+09:00` のようなタイムゾーン付き日時 |
| `end_at` | ○ | 開始より後の日時 |
| `dj_name` | ○ | `djs.name` と完全一致するDJネーム、または `名義 (DJ1,DJ2)` 形式の出演名義 |

`2027/11/7 13:00` などの自動変換を避けるため、日時列は「書式なしテキスト」にしてください。同一フロアの出演時刻の重複、未登録のフロア・DJはエラーになります。日ごとのフロア数は出演枠から決定します。

出演枠は、フロアIDと日付を含む開始日時の組で識別します。異なる日・異なるフロアの同時刻の出演枠は別の枠として扱います。`slot_id` は使用しません。旧シートに列が残っていても、その値は無視します。

B2Bなどの複数人の出演は、同じセルに `AO B2B Nagi (DJ AO,Nagi)` と入力します。末尾の半角括弧内を参加DJ一覧として読み取り、カードには `AO B2B Nagi` だけを表示します。3人以上も同じ形式で指定でき、参加DJはそれぞれ `djs` に個別登録してください。プロフィールのオーバーレイ内でDJを選ぶと、その人の画像・ジャンル・プロフィール・SNS・推し曲・出演予定を表示します。出演予定にはソロとB2Bの両方が含まれます。

B2B名義自身の情報も、`djs` に別の行として登録できます。上の例では `name` を括弧より前の `AO B2B Nagi` とし、名義自身の画像・ジャンル・プロフィール・SNS・推し曲を設定してください。カードは名義自身の画像・ジャンルを表示し、オーバーレイは最初に名義のプロフィールを開きます。名義と参加DJのプロフィールを切り替えられ、名義自身の出演予定も表示します。名義の行がない場合は、参加DJの情報を表示します。

B2B名義の `image_url` が未設定の場合は、参加DJの画像を組み合わせた正方形のコラージュを、カード・プロフィール・名義選択ボタンに表示します。2人は左右に、3人以上は複数段に配置します。個別DJの画像も未設定の場合は、その人の部分に自動生成アイコンを使用します。名義自身の画像を設定すると、その画像を優先します。

プロフィール側の `name` も `AO B2B Nagi (DJ AO,Nagi)` と記載できます。タイムテーブルで指定したB2B名義については、プロフィール側も括弧より前の名義を抽出して照合します。括弧の前や参加DJ名の前後の空白は無視します。通常の個人DJ名に含まれる括弧はそのまま保持します。括弧付きと括弧なしで同じ名義を二重登録するとエラーになります。

DJ名や名義に記号を含める場合、`dj_name` では `\(`・`\)`・`\,`・`\\` とエスケープします。例：`DJ AO \(Guest\)` はソロ名 `DJ AO (Guest)`、`Special \(B2B\) (DJ AO \(Guest\),A\,B)` は名義 `Special (B2B)`、参加DJ `DJ AO (Guest)` と `A,B` です。`djs.name` にはエスケープせず元の名前を登録します。括弧の不整合、空の名義・参加者、同一枠内のDJ重複、不明なエスケープはエラーになります。CSVを手書きする場合は、カンマを含むセル全体を二重引用符で囲んでください（スプレッドシートからのCSV出力では自動処理されます）。

#### djs

| 列 | 必須 | 内容 |
| --- | --- | --- |
| `name` | ○ | 一意のDJネームまたはB2B名義。前後の空白を除いて完全一致で照合 |
| `genres` | ○ | ジャンル。`House / Disco` などの自由記述 |
| `profile` | ○ | プロフィール本文。改行可能 |
| `image_url` | | HTTPSの公開画像URL、サイト内の相対パス、または同一オリジンで有効な `blob:` 画像URL。正方形を推奨（中央を基準に1:1で表示） |
| `link_url` | | SNS・ホームページなどのURL。カンマ区切りで複数指定可能 |
| `favorite_track_url` | | 推し曲の共有URL。列名 `推し曲` も使用可能 |

プロフィールとジャンルは列自体が必須です。値は空欄にできます。推し曲はSpotify・SoundCloud・YouTubeの公式iframeに対応します。Spotifyの通常・`intl-ja`・埋め込みURLを受け付けます。SoundCloudは `https://soundcloud.com/ユーザー/曲名` の完全URLと `https://on.soundcloud.com/…` の短縮URLに対応します。短縮URLはプロフィール表示時に公式oEmbed APIで解決し、成功した結果はページを開いている間再利用します。取得できない場合は元の曲ページへのリンクを表示します。YouTubeは `youtube.com/watch?v=動画ID`・`youtu.be/動画ID`・Shorts・ライブ・埋め込みURLを受け付け、`youtube-nocookie.com` のプレーヤーで自動再生せずに表示します。動画IDのないプレイリストやその他の安全なHTTP(S) URLはリンクとして表示し、任意のHTMLは埋め込みません。元の曲ページへのリンクも残します。空欄の場合は推し曲欄を隠します。

`image_url`・`link_url`・`favorite_track_url` は、値の空欄だけでなく列自体も省略できます。画像なしの場合は自動生成アイコンを表示し、SNSリンク・推し曲なしの場合はそれぞれの項目を非表示にします。

`blob:` はプロフィール画像（B2Bの参加DJ画像を含む）に限り、現在のサイトと同じオリジンのものを受け付けます。リンクや推し曲のURLとしては使用しません。一時URLはブラウザー内のデータを指し、元ページを閉じる・URLを破棄するなどで使えなくなるため、スプシから来場者全員に画像を配る用途にはHTTPSの公開画像URLを使用してください。他サイトでコピーした `blob:` URLを公開画像URLに変換する機能ではありません。読み込めない画像は自動生成アイコンに戻します。[blob URLの制約（MDN）](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Schemes/blob)を参照してください。

`link_url` は、1つのセルに `https://x.com/example, https://soundcloud.com/example` のように半角カンマで区切って入力できます。前後の空白・空の項目・重複URLは除き、各リンクにFQDNと取得可能なfaviconを表示します。安全なHTTP(S)リンクのみ表示します。URL自体にカンマを含める場合は `%2C` と記述してください。CSVを手書きする場合、複数URLを入れたセル全体を二重引用符で囲みます。

画像未設定のDJには、DJ名を基に固定した幾何学模様のSVGアイコンをブラウザー内で生成します。紹介文（`profile`）のキーワードに応じ、「温かい・柔らかい」は丸い図形、「ミニマル・反復」は整列した小さな四角、「浮遊感・アンビエント」は余白の多い点、「跳ねる・軽快・疾走感」は短い斜線を使用します。複数の特徴がある場合は、点・丸・斜線・四角の順で形を選び、反復の表現があれば整列を優先します。該当語がない場合は基本模様を使います。配色は青・緑・黄土・赤紫・紫・青緑の低彩度6系統から、DJ名に基づいて固定します。背景と模様を同じ系統で揃え、ライト・ダーク表示に対応します。紹介文の変更や重複回避の再生成では色を変えません。生成時に外部サービスへの通信は行いません。

自動生成アイコンの右下には、団体のシンボルロゴを控えめに重ねて表示します。文字の「仮」表示は付けません。B2Bのコラージュでも、生成アイコンの領域ごとにロゴを表示します。登録されたプロフィール画像にはロゴを重ねません。

登録DJ内で生成SVGが重複した場合は、模様を再生成して重複を避けます。同じDJ名・同じキーワード分類・同じ登録内容であれば、CSVの行順にかかわらず同じアイコンになります。DJ名やキーワード分類の変更時にはアイコンも変わる場合があります。設定済みの画像を優先し、画像の読み込みに失敗した場合にも、そのDJの生成アイコンを表示します。

`djs.name` にも `schedule.dj_name` と同様のエスケープを付けられます。たとえば `M2B2-A\(松葉杖\)` と `M2B2-A(松葉杖)` は、出演枠のDJ名に合わせて同じ名前として照合します。リテラル表記の完全一致を優先し、一致しない場合だけエスケープを解除して照合します。同じDJを両表記で二重登録するとエラーになります。

DJネームは大文字小文字を区別します。名前を変更するときは、両タブの値を揃えてください。両CSVを一組として検証し、どちらかが不正なら直前の正常データを使います。

## 画面の動作

- 開催前：全日程・開催する全フロアを表示し、Twitchチャンネルのフォローへ誘導します。
- 初回開演後：日付・フロアを選択する表示に切り替えます。「全日程を見る」も利用できます。
- 最終終演後：全日程を表示し、日付・フロア別の確認にも戻れます。
- 配信ページ：フロアのみを切り替えます。開催日は現在日時から選び、前・現在・次のDJを表示します。休憩中は現在枠を作らず、直前のDJを残します。
- DJプロフィール：右側のオーバーレイ（スマートフォンでは下からのシート）で表示します。閉じるボタン・背景・Escで閉じ、元のボタンにフォーカスを戻します。プロフィールの開閉やデータ更新ではTwitch iframeを作り直しません。

出演カードの左上に、日付・フロアごとに開始時刻順で `01` から通し番号を表示します。全日程・開演後・配信ページで同じ出演枠には同じ番号を使用します。

フロアは `config.floors` の順に、青のアクセントと、同じ色相で彩度を落として明度を上げたアクセントを使います。1つ目は実線、2つ目は破線を併用し、見出し・通し番号・フロア選択・配信ページで区別を揃えます。

複数フロアの境界には薄い区切り線を表示します。横並びでは縦線、幅850px以下の縦並びでは横線に切り替えます。

表示は閲覧端末の時計と予定時刻に基づきます。実際の配信状態をAPIで判定するものではありません。時刻が押した場合はスプレッドシートの予定時刻を変更できます。直前の正常データはブラウザにも保存し、更新に失敗したことを画面に表示します。スプレッドシート側の公開キャッシュにより反映が遅れる場合があります。

本番ビルドでは、読み込み済みの予定に基づく現在・前・次のDJや開演状態の切り替えは継続します。スプレッドシートで変更した予定・プロフィールを取得するには、ページを再読み込みしてください。取得失敗時の「再読み込み」ボタンでも再取得できます。ページ移動による初回取得は行われます。

### OBS用Now Playing

`/now-playing.html?floor=floor-1` は、背景透過のOBSブラウザーソース用ページです。`floor=floor-2` で2つ目のフロアを指定します。省略時は設定の最初のフロアを使用し、未定義のフロアIDでは表示しません。

読み込んだタイムテーブルとOBSを動かす端末の時計を使い、1秒ごとに出演枠を判定します。開始時刻を含み、終了時刻には次の枠へ切り替わります。開演前・休憩中・終演後は何も表示しません。日付をまたぐ出演枠にも対応します。DJ名・ジャンル・予定時間・正方形のプロフィール画像を画面左下に表示し、B2Bの名義情報や画像合成・自動生成アイコンも共通のデータを使います。曲の再生や推し曲プレーヤーの表示は行いません。

OBSでは「ソースを追加 → ブラウザ」で、配信するサイトの `/now-playing.html?floor=floor-1` をURLに指定してください。幅1920・高さ1080を基準に配置しています。キャンバスが1280×720の場合は、その幅・高さに合わせてください。「ローカルファイル」はオフにし、ローカルで使う場合も開発サーバーなどのHTTP URLを指定します。ブラウザーソースの設定については[OBS公式ドキュメント](https://obsproject.com/kb/browser-source)を参照してください。

本番ではCSVを初回のみ取得します。端末の時計による自動切り替えは続きますが、スプシの変更を取り込むにはOBSのブラウザーソースを再読み込みしてください。取得失敗時に保存済みの正常データがあれば使用し、なければ非表示を維持します。エラーはブラウザーのコンソールに記録し、配信映像には重ねません。時刻が押した場合も自動追従はしないため、予定を修正して再読み込みしてください。

Vite開発中は `?floor=floor-1&preview=during` で指定フロアの出演中表示を確認できます。`preview=before`・`preview=after` は非表示確認用です。本番では `preview` を無視して実際の現在時刻を使用します。

### Twitch

現在のホスト名を `parent` に自動設定します。サイト全体を別のiframeに埋め込む場合は、外側のホスト名を `twitch.additionalParents` に追加してください。値は `example.com` のようにホスト名のみです。

Twitchプレーヤーはスマートフォンの縦向きでもページ内に表示します。iframe内のサイズは最小400×300pxを確保し、それより狭い表示領域では操作部を含むプレーヤー全体を画面幅に合わせて縮小します。画面サイズや向きの変更では映像・コメントのiframeを作り直しません。コメントは縦に続けて表示します。Twitch側のログイン状態・ブラウザのストレージ設定により、コメントへのログインが別途必要な場合があります。

参考：[Twitch映像](https://dev.twitch.tv/docs/embed/video-and-clips/)、[Twitchコメント](https://dev.twitch.tv/docs/embed/chat/)、[Spotify](https://developer.spotify.com/documentation/embeds/tutorials/creating-an-embed)、[SoundCloud](https://developers.soundcloud.com/docs/api/html5-widget/)。

## 検証・配置

### Cloudflare Workers / Wrangler

```sh
npm run dev:worker
```

WranglerがCloudflare用にビルドし、表示されたローカルURLから静的ページとCSVキャッシュ用Workerを確認できます。通常のVite開発は引き続き `npm run dev` を使用します。Wranglerでは本番と同様にCSVの定期取得を行いません。

`wrangler.jsonc` でWorker名、互換日付、静的ファイルの出力先とCache APIのTTLを設定しています。`CSV_CACHE_TTL_SECONDS` の初期値は120秒です。取得元の公開CSV URLは引き続き `config.js` で管理します。Cloudflare用ビルドでは、出力した `dist/config.js` の取得先だけを `/api/schedule.csv` と `/api/djs.csv` に切り替えます。元の設定ファイルは変更しません。サンプルモードではローカルCSVを使います。

HTML・CSS・画像などは静的アセットとして配信し、`/api/*` ではWorkerを優先します。正常なCSVの構文と必須列を検証してキャッシュし、上流のエラーやHTMLは保存しません。DJと出演枠の整合性は、従来どおりブラウザーで両CSVを合わせて検証します。レスポンスの `X-Data-Cache` は `HIT` / `MISS`（サンプルAPIは `SAMPLE`）です。

Cache APIの保存内容はデータセンターごとに分かれ、TTL以内でも削除される場合があります。キャッシュ切れと同時にアクセスが集中すると、上流への取得が複数発生する可能性があります。変更の反映には最大で設定TTLに加え、Google側の公開キャッシュによる遅れが生じます。ブラウザーで読み込み済みの内容の更新には再読み込みが必要です。ローカルのキャッシュは本番環境とは別です。[Cloudflare Cache API](https://developers.cloudflare.com/workers/runtime-apis/cache/)、[静的アセットのルーティング](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/)を参照してください。

```sh
npm run check:worker
```

デプロイせずにビルドとWorkerのバンドルを確認します。公開する場合は、Cloudflareの認証後に `npx wrangler deploy` を実行します。このリポジトリではアカウントID・独自ドメインのルートを固定していません。必要に応じて公開先を設定してください。

### 通常の静的ホスティング

```sh
npm test
npm run build
npm run preview
```

ビルドは既存の静的ファイルのコピー処理を使用します。`npm run preview` で `http://localhost:4173` から出力を確認できます。生成された `dist/` の内容を静的ホスティングへ配置できます。サーバー側の処理や秘密鍵は不要です。`index.html` と `live.html` の相対リンクなので、サブディレクトリへの配置にも対応します。

ロゴは支給された `LOGO_MARK&TYPO.ai` のベクターパスから取り出し、`assets/frenzy-symbol.svg` と `assets/frenzy-wordmark.svg` に保存しています。画像未設定時はDJごとの自動生成アイコンを使います。背景は単色、TDUの青 `#2D56A0` をアクセントに使用し、カードの角丸は2pxです。ヘッダーの背景シンボルは `showLogoBackdrop` で切り替えられます。
